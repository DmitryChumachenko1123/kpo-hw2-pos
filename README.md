# ПОС - преподавательская оценка студентов

Консольное приложение на C# (.NET 10): студенты, рубрикатор, оценки по критериям, итог по весам и выгрузка в CSV.

## Запуск

```
dotnet run --project src/Pos            # меню, данные сохраняются в папку pos-data
dotnet run --project src/Pos -- --demo  # сквозной сценарий из задания
dotnet test                             # тесты
```

Демо добавляет студентов и критерии, выставляет оценки, пробует нарушить правила (12 из 10,
несуществующий критерий и т.д.), считает итог и выгружает его в CSV.

## Предметная область и DDD

Словарь: **студент** (`Student`), **критерий** (`Criterion`) с максимумом (`MaxScore`) и весом (`Weight`),
**рубрикатор** (`Rubric`) - набор критериев, **оценка** (`Evaluation`) с баллом (`Score`), **итог** (`FinalGrade`).

**Entity и Value Object.** `Student`, `Criterion`, `Evaluation` - сущности: у них есть `Id`, и, например,
исправленная оценка остаётся той же оценкой. `Score`, `MaxScore`, `Weight` - value objects: у них нет `Id`,
они сравниваются по значению и проверяют себя при создании (нельзя создать `Score(-1)` или `Weight(0)`).

**Агрегаты.** `Rubric` владеет критериями: добавить или удалить критерий можно только через него, он же следит
за уникальностью названий. `Student` и `Evaluation` - отдельные агрегаты, связаны с остальными по `Id`.
Оценки не стал класть внутрь студента: их правят по одной, и так проще хранить.

**Инварианты:**
- балл от 0 до максимума критерия - `Score` (не меньше 0) и `Criterion.CheckScore` (не больше максимума),
  проверяется при выставлении и при исправлении;
- оценка только по критерию из рубрикатора - `EvaluationFactory` берёт критерий через `Rubric.Get`;
- одна оценка на критерий у студента (повторно - только исправление) - `PosFacade.Grade`;
- нельзя удалить критерий, по которому есть оценки - `Rubric.RemoveCriterion`;
- итог согласован с оценками - он не хранится, а каждый раз считается заново в `FinalGradeCalculator`.

**Repository.** Интерфейсы `IStudentRepository`, `IRubricRepository`, `IEvaluationRepository` лежат в Domain,
реализации на JSON-файлах - в Infrastructure.

**Domain Service.** `FinalGradeCalculator` - расчёт итога. Ему нужны студент, рубрикатор и оценки сразу,
поэтому он не метод какой-то одной сущности. Формула: `итог = 10 * Σ(вес * балл / максимум) / Σ вес`.
Веса нормируются, их не нужно подгонять под 100%. Округление в ведомость арифметическое (7.5 -> 8).

## Архитектура

Выбрал Ports and Adapters, облегчённый вариант: один проект, слои разнесены по папкам.

```
src/Pos/
  Domain/          сущности, VO, инварианты, FinalGradeCalculator, интерфейсы репозиториев
  Application/     PosFacade (сценарии), порт IReportExporter
  Infrastructure/  JSON-репозитории, CsvReportExporter
  ConsoleUi/       меню, ввод, демо
  Program.cs       composition root (DI)
```

Зависимости направлены внутрь:

```
ConsoleUi ──► Application ──► Domain ◄── Infrastructure
```

Domain ни от чего не зависит. Infrastructure реализует интерфейсы из Domain и Application (порты).
Все зависимости собираются в `Program.cs` через `Microsoft.Extensions.DependencyInjection`.

## Паттерны GoF

- **Factory (порождающий)** - `EvaluationFactory`. Единая точка создания оценки: берёт критерий из
  рубрикатора (если его там нет - ошибка) и создаёт оценку через `Evaluation.Create`, который проверяет
  балл по максимуму критерия. Конструктор `Evaluation` закрытый, поэтому оценку без проверки балла не создать.
- **Facade (структурный)** - `PosFacade`. Консоль не работает с репозиториями, фабрикой и калькулятором
  напрямую: каждый сценарий - один метод фасада. Логика не размазана по меню.
- **Strategy (поведенческий)** - `IFinalGradePolicy`, реализации `WeightedTotalPolicy` (нет оценки = 0, для
  финальной ведомости) и `CurrentProgressPolicy` (учитываются только выставленные оценки, для текущей
  успеваемости). Правило переключается в меню, новое добавляется отдельным классом без изменения калькулятора.
